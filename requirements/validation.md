# Wymagania: walidacja dokumentu

Decyzje: `docs/adr/0008-document-validation.md`. Rekomendacja: XML Schema Part 1: Structures Second Edition
(2004-10-28), rozdziały 3 (Validation Rules) i 5 oraz punkt 4.3.2; część 2 dla wartości typów prostych. Pakiet:
`internal/validate`, API: `xsd.(*Set).Validate`, `xsd.(*Set).ValidateDocument`.

| Id | Wymaganie |
|---|---|
| VAL-001 | Element główny jest oceniany ściśle według deklaracji globalnej o swojej nazwie; bez niej (i bez poprawnego `xsi:type`) błąd `cvc-elt.1` (3.3.4, Schema-Validity Assessment (Element)). |
| VAL-002 | Element o deklaracji abstrakcyjnej daje `cvc-elt.2`, a element o typie abstrakcyjnym `cvc-type.2` (3.3.4). |
| VAL-003 | `xsi:nil`: przy deklaracji bez `nillable` błąd `cvc-elt.3.1`; `xsi:nil="true"` wymaga braku znaków i elementów dzieci (`cvc-elt.3.2.1`) i braku wartości stałej (`cvc-elt.3.2.2`); niepoprawna wartość logiczna to błąd typu `boolean`. |
| VAL-004 | `xsi:type`: wartość musi być poprawnym QName w przestrzeniach nazw elementu (`cvc-elt.4.1`), wskazywać typ (`cvc-elt.4.2`) poprawnie wyprowadzony z typu deklaracji przy blokadach z `block` deklaracji i typu (`cvc-elt.4.3`, Type Derivation OK 3.4.6 i 3.14.6); poprawny typ lokalny zastępuje typ deklaracji. |
| VAL-005 | Wartość domyślna i stała elementu (`cvc-elt.5`): pusty element dostaje wartość domyślną sprawdzaną typem faktycznym (`cvc-elt.5.1.1`); przy wartości stałej treść prosta musi odpowiadać jej postaci kanonicznej w przestrzeni wartości typu faktycznego (`cvc-elt.5.2.2.2.2`), treść mieszana tekstowi wartości (`cvc-elt.5.2.2.2.1`), a elementy dzieci są niedozwolone (`cvc-elt.5.2.2.1`). |
| VAL-006 | Dzieci elementu o treści elementowej albo mieszanej są dopasowywane do modelu zawartości (3.9.4) automatem z etapu 4; dziecko spoza modelu albo niepełna treść to `cvc-complex-type.2.4` z listą oczekiwanych elementów. Po pierwszym błędzie modelu dalsze dzieci są oceniane luźno. |
| VAL-007 | Rodzaje treści (`cvc-complex-type.2.1`–`2.3`, `cvc-type.3.1`): treść pusta nie ma znaków ani elementów (także białych znaków), treść prosta i typ prosty nie mają elementów dzieci, treść elementowa nie ma znaków innych niż białe. |
| VAL-008 | Atrybuty (`cvc-complex-type.3`, `4`, `5`; `cvc-attribute`; `cvc-au`): atrybut z użyciem jest sprawdzany jego deklaracją i wartością stałą; inny wymaga symbolu wieloznacznego (`3.2.1`) o pasującej przestrzeni (`3.2.2`) i jest oceniany według `processContents` (strict bez deklaracji globalnej: `cvc-attribute.1`); brak wymaganego atrybutu to `cvc-complex-type.4`; najwyżej jeden atrybut typu ID przez symbol wieloznaczny (`5.1`, `5.2`). Atrybuty `xsi:type`, `xsi:nil`, `xsi:schemaLocation` i `xsi:noNamespaceSchemaLocation` są wyłączone z tego sprawdzania; element o typie prostym nie ma innych atrybutów (`cvc-type.3.1.1`). |
| VAL-009 | Wartości typów prostych w atrybutach i treści są sprawdzane przez `internal/datatypes` (String Valid 3.14.4, część 2 4.1.4) po normalizacji białych znaków; błąd ma kod reguły części 2 (np. `cvc-pattern-valid`, `cvc-maxInclusive-valid`), wartość (`Value`) i naruszony aspekt (`Facet`). |
| VAL-010 | Symbole wieloznaczne elementów: `skip` pomija poddrzewo, `lax` ocenia element według deklaracji globalnej, jeśli jest, a inaczej luźno; `strict` wymaga deklaracji globalnej (albo `xsi:type`), bez niej `cvc-elt.1`. Elementy o typie `anyType` mają dzieci i atrybuty oceniane luźno. |
| VAL-011 | Tabela ID/IDREF (3.15.5, `cvc-id`): wartości typów ID, IDREF i IDREFS (także z wartości domyślnych atrybutów); powtórzone ID to `cvc-id.2`, IDREF bez ID w dokumencie to `cvc-id.1` na końcu dokumentu. |
| VAL-012 | Ograniczenia tożsamości (3.11.4, 3.11.5) strumieniowo, z podzbiorem XPath z 3.11.6: pole wskazujące więcej niż jeden węzeł albo węzeł bez typu prostego to `cvc-identity-constraint.3`; powtórzony ciąg kluczowy `unique` to `4.1`; `key` bez pola `4.2.1`, powtórzony `4.2.2`, pole z elementem nilled `4.2.3`; `keyref` bez pasującego klucza w tabeli węzłów (także z potomków) `4.3`. Równość ciągów kluczowych w przestrzeni wartości. |
| VAL-013 | Wartości zależne od dokumentu i schematu: QName i NOTATION rozwiązywane przestrzeniami nazw elementu; NOTATION musi być notacją ze schematu (`cvc-notation`), ENTITY nazwą zadeklarowanej encji nieparsowanej (`cvc-entity`). |
| VAL-014 | Wskazówki `xsi:schemaLocation` i `xsi:noNamespaceSchemaLocation` są domyślnie pomijane; z `Config.SchemaLocationHints` wskazane dokumenty są czytane wyłącznie z `fs.FS` (Locations albo ścieżka względna wobec nazwy dokumentu), a wskazówka dodająca dokument po pierwszym wystąpieniu elementu albo atrybutu jej przestrzeni to błąd `schema-location-hint` (4.3.2). |
| VAL-015 | Każdy błąd dokumentu ma stały kod, wiersz i kolumnę z czytnika, ścieżkę elementu (`/a/b[2]/@c`: nazwy lokalne, `[n]` od drugiego wystąpienia nazwy wśród rodzeństwa), nazwę węzła i komunikat po angielsku. |
| VAL-016 | Walidacja zbiera wszystkie błędy w kolejności dokumentu do `MaxErrors` (domyślnie 1000); po przekroczeniu zwraca je razem z `ErrTooManyErrors`. |
| VAL-017 | Błąd dobrej formy z czytnika jest błędem dokumentu z kodem czytnika; konstrukcja nieobsługiwana (encja zewnętrzna) daje `errors.ErrUnsupported`, a przekroczenie limitu (czytnika, tekstu, wpisów ID i ograniczeń tożsamości, konfiguracji dopasowania) `ErrLimit` jako drugi wynik, nie werdykt o dokumencie. |
| VAL-018 | Walidacja jest strumieniowa: pamięć nie zależy od rozmiaru dokumentu, plik JPK 1 GB waliduje się w mniej niż 64 MB (kryterium K6). |
| VAL-019 | Ten sam dokument i schemat dają te same błędy w tej samej kolejności, także przy równoczesnej walidacji wielu dokumentów jednym `Set`. |
| VAL-020 | Ustawienia domyślne są bezpieczne: bez sieci, bez encji zewnętrznych, bez wskazówek lokalizacji, z limitami głębokości i liczby wpisów. |
| VAL-021 | Testy dokumentów zestawu W3C objęte zakresem dają oczekiwany werdykt (kryterium K1, `TestW3CSuite`), a korpus MF i dokumenty syntetyczne werdykt, kod, wiersz i ścieżkę z `testdata/instances/expected.json` (kryterium K2, `TestInstanceCorpus`). |
| VAL-022 | Członek grupy podstawienia zastępuje głowę w modelu zawartości z wyłączeniem deklaracji abstrakcyjnych i zablokowanych (3.3.6, Substitution Group OK (Transitive)); element dopasowany jest oceniany deklaracją członka. |
