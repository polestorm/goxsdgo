# Wymagania: wczytanie schematu

Pakiet `internal/schema`, wywoływany przez `xsd.Config.Compile`. Decyzje: `docs/adr/0006-schema-loading.md`. Źródło:
XML Schema Part 1: Structures Second Edition (W3C, 2004-10-28), rozdziały 3 i 4 oraz dodatek A, i Part 2: Datatypes
Second Edition, dodatek A (schemat dla schematów). Nazwy w nawiasach to identyfikatory reguł z rekomendacji i zarazem
kody błędów. Testy: `internal/schema/schema_test.go`, `TestW3CSuite` (testy schematów zestawu W3C),
`TestSchemaCorpus` (schematy MF).

| Id | Wymaganie |
|---|---|
| SCH-001 | Dokument schematu jest czytany czytnikiem z etapu 1 (dobra forma i przestrzenie nazw); błąd dobrej formy daje `sfs-not-well-formed` z wierszem i kolumną. Element główny musi być `xs:schema`: inaczej `sfs-not-schema` (dokument podany wprost) albo `src-include.1`, `src-redefine.1`, `src-import.1` (dokument wskazany przez include, redefine, import). Konstrukcja, której czytnik nie obsługuje (encje zewnętrzne), daje błąd opakowujący `errors.ErrUnsupported`, nigdy werdykt. |
| SCH-002 | Każdy element z przestrzeni XSD jest sprawdzany według schematu dla schematów (część 1 i 2, dodatek A) w kontekście rodzica (np. `topLevelElement`, `localElement`, `narrowMaxMin`): kolejność i liczba dzieci (`sfs-content`), tekst w treści elementowej (`sfs-text`), atrybuty bez przestrzeni nazw spoza listy i atrybuty z przestrzeni XSD (`sfs-attribute`), brak wymaganego (`sfs-attribute-required`), wartości atrybutów według ich typów, także `xml:lang`, `xml:space`, `xml:base`, `xml:id` (`sfs-attribute-value`), powtórzone wartości typu ID w dokumencie (`sfs-duplicate-id`). Atrybuty z innych przestrzeni są dozwolone. |
| SCH-003 | Wartość QName jest interpretowana według [in-scope namespaces] swojego elementu (QName Interpretation, 3.15.3); prefiks bez deklaracji daje `src-qname`. Rozwiązanie (QName resolution (Schema Document)) wymaga komponentu właściwego rodzaju (`src-resolve`) w przestrzeni, która jest docelową przestrzenią dokumentu albo jest importowana (`src-resolve.4.1`, `src-resolve.4.2`). Przestrzeń XSD jest zawsze dostępna; deklaracje atrybutów `xml:lang`, `xml:space`, `xml:base`, `xml:id` i czterech atrybutów xsi są wbudowane. Nierozwiązane odwołanie jest błędem schematu (zob. `docs/differences.md`, grupa Missing). |
| SCH-004 | Dokumenty pochodzą wyłącznie z `fs.FS`; biblioteka nie sięga do sieci. `schemaLocation` jest rozwiązywane przez `Config.Locations` (adres dosłowny albo po rozwiązaniu względem adresu dokumentu), potem jako ścieżka względna w `fs.FS` z dokładną wielkością liter i bez wyjścia poza `fs.FS`. Import bez `schemaLocation` albo z adresem nierozwiązywalnym korzysta z `Config.Namespaces`. Nierozwiązane include i import nie są błędem (4.2.1, 4.2.3); redefine z dziećmi wymaga rozwiązania (`src-redefine.1`). Import przestrzeni XSD jest pomijany. |
| SCH-005 | Include (4.2.1): dokument włączany ma tę samą docelową przestrzeń albo nie ma jej wcale (`src-include.2.1`). Dokument bez przestrzeni włączony do dokumentu z przestrzenią (kameleon) dostaje jego przestrzeń: w nazwach komponentów, w nazwach lokalnych z `form="qualified"`, w odwołaniach QName bez przestrzeni i w symbolach wieloznacznych (`##targetNamespace`, `##other`). Ten sam plik włączony kilka razy z tą samą przestrzenią daje te same komponenty. |
| SCH-006 | Import (4.2.3): `namespace` różny od docelowej przestrzeni dokumentu (`src-import.1.1`); import bez `namespace` tylko w dokumencie z przestrzenią (`src-import.1.2`); dokument importowany ma przestrzeń z `namespace` (`src-import.3.1`) albo, gdy `namespace` brak, nie ma jej (`src-import.3.2`), także gdy był już wczytany. |
| SCH-007 | Redefine (4.2.2): dokument redefiniowany ma tę samą przestrzeń albo żadnej (`src-redefine.3.1`); redefinicja zastępuje komponent wszędzie, także w dokumencie redefiniowanym; redefiniowany typ prosty jest restrykcją, a złożony restrykcją albo rozszerzeniem samego siebie (`src-redefine.5`), a jego typ bazowy to oryginał; grupa odwołuje się do siebie najwyżej raz, z `minOccurs` i `maxOccurs` równymi 1 (`src-redefine.6.1.1`, `src-redefine.6.1.2`); grupa atrybutów najwyżej raz (`src-redefine.7.1`), a bez odwołania do siebie jest restrykcją oryginału (`src-redefine.7.2.2`); redefiniowany komponent musi istnieć w dokumencie redefiniowanym albo w jego włączeniach (`src-redefine`). Dozwolone są łańcuchy redefinicji. Punkt 6.2.2 (restrykcja grupy) sprawdza etap 4. |
| SCH-008 | Schema Properties Correct (3.15.6): w każdej przestrzeni symboli (typy, elementy, atrybuty, grupy atrybutów, grupy modelu, notacje, ograniczenia tożsamości) nazwa występuje raz (`sch-props-correct.2`); `targetNamespace=""` jest błędem (`sch-props-correct.1`). |
| SCH-009 | Typy proste (3.14): restriction ma `base` albo `simpleType`, nie oba (`src-simple-type.2`), list `itemType` albo `simpleType` (`src-simple-type.3`); unia bez cyklu (`src-simple-type.4`) i z co najmniej jednym typem składowym, spłaszczana; typ bazowy prosty (`st-props-correct.1`), bez cyklu (`st-props-correct.2`), bez `restriction` w `{final}` (`st-props-correct.3`); anySimpleType nie jest typem bazowym restrykcji (`cos-st-restricts.1.1`); typ elementu listy atomowy albo unia bez list (`cos-st-restricts.2.1`) i bez `list` w `{final}` (`cos-st-restricts.2.3.1.1`); typy składowe unii bez `union` w `{final}` (`cos-st-restricts.3.3.1.1`). Aspekty sprawdza pakiet `datatypes` z kodami części 2. |
| SCH-010 | Deklaracje i użycia atrybutów (3.2, 3.5): `src-attribute.1`–`.4`; wartość domyślna albo stała poprawna dla typu (`a-props-correct.2`); typ ID bez wartości (`a-props-correct.3`); nazwa różna od `xmlns` (`no-xmlns`); przestrzeń różna od xsi (`no-xsi`); użycie deklaracji ze stałą wartością tylko z tą samą stałą wartością (`au-props-correct.2`); typ NOTATION bez enumeration niedozwolony (`enumeration-required-notation`); `use="prohibited"` nie tworzy komponentu. |
| SCH-011 | Deklaracje elementów (3.3): `src-element.1`, `.2.1`, `.2.2`, `.3`; wartość domyślna albo stała poprawna (`e-props-correct.2`, w tym `cos-valid-default.2.1` i `cos-valid-default.2.2.2`); typ elementu wyprowadzony z typu głowy grupy podstawienia z uwzględnieniem jej `{substitution group exclusions}` (`e-props-correct.4`); typ ID bez wartości (`e-props-correct.5`); grupy podstawienia bez cyklu (`e-props-correct.6`); bez typu element dostaje typ głowy grupy podstawienia, a bez głowy anyType. `minOccurs=maxOccurs=0` nie tworzy cząstki. |

| SCH-013 | Ograniczenia typów złożonych (3.4.6): `ct-props-correct.2`–`.5`; Derivation Valid (Extension) `cos-ct-extends.1.1`, `.1.3`, `.1.4`, `.1.4.1`, `.1.4.3.2.2.1`, `.2.2`; Derivation Valid (Restriction, Complex) `derivation-ok-restriction.1`, `.2.1.1`, `.2.1.2`, `.2.1.3`, `.2.2`, `.3`, `.4.1`–`.4.3`, `.5.2`, `.5.2.2.1`, `.5.3`, `.5.4`, `.5.4.1.2`.
