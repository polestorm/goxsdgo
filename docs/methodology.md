# How the comparison is measured

Every number in the README comparison and in [comparison.md](comparison.md) can be reproduced from this
repository with public tools and public data. This page lists the inputs, the settings of each candidate, how
each row is computed, where the raw results are, and how to run it all again.

## Inputs

All inputs are fetched by `tools/fetch` (Go, or `python tools/fetch/fetch.py`) according to
[`testdata/sources.json`](../testdata/sources.json), which pins every source to a commit or a published file and a
SHA-256 checksum of the extracted tree; nothing is downloaded during a measurement. Every file that comes from a
government server (the MF schemas and samples) or from w3.org also has a second address in the public mirror
[polestorm/goxsdgo-testdata](https://github.com/polestorm/goxsdgo-testdata), pinned to a commit; `tools/fetch` tries
the original address first, and the checksum must match either way.

| Input | Source | Used for |
|---|---|---|
| W3C XML Schema test suite | `w3c/xsdtests` at commit `7bc3365c`; cases in scope for XSD 1.0 Second Edition as read by `internal/w3c` (39,439) | W3C rows, contested cases, agreement with libxml2 |
| `xml.xsd`, `xlink.xsd` | local copies of the w3.org schemas some cases import (`testdata/sources.json`, `w3c-schemas`) | W3C rows (served offline) |
| MF schemas | the 170 schemas published by the Polish Ministry of Finance (JPK, KSeF, e-Sprawozdania) with their imports | MF rows |
| MF samples and synthetic documents | 8 published MF sample files and 7 synthetic documents listed in [`testdata/instances/expected.json`](../testdata/instances/expected.json) with their expected verdicts | MF rows |
| 20, 60, 200 MB documents | generated deterministically by `tools/bench` (`syntheticJPK` in `tools/bench/perf.go`) from the MF sample `testdata/instances/mf/jpk_v7m_3_organization.xml`: its `SprzedazWiersz` row repeated up to the size; fictitious data | time and memory rows |
| 1 GB document | generated by `TestStreamingMemory` (`xsd/streaming_test.go`) with `GOXSDGO_STREAM_MB=1024` | 1 GB row |
| safety and feature probes | small schemas and documents written by `tools/bench/probes.go`; a local HTTP server counts requests | safety, features, errors rows |

No row of the comparison uses private data. The internal acceptance records (in Polish) also contain aggregate
figures from a private corpus of client files, which cannot be published; they are not part of the comparison.

## Candidates and their settings

| Candidate | Version | How it is run |
|---|---|---|
| goxsdgo | this repository | `xsd.Config` with a location catalogue for imports; `SchemaLocationHints` on for cases that name their schema only in the document; a second run with `NameRules: NamesXML10Edition5` |
| libxml2 | 2.15.4 (see below) | through its C API from `tools/compare` (cgo, schema compiled from one file, no hints) and as `xmllint --stream --nonet` with an XML catalogue for time and memory |
| knroy/go-xml | v2.3.1 | XSD 1.0 mode; a resolver serving local files; DOCTYPE allowed in suite documents (its default refuses it) |
| jacoelho/xsd | v0.6.15 | default options; for the 200 MB file the input limit (`MaxInstanceBytes`, 64 MiB by default) is raised |
| cB-Sigma/xsd | v1.0.0 | a fetch function serving local files; `LoadHinted` for hint-only cases |

Versions are pinned in `tools/bench/go.mod` (the latest tags on 2026-11-25). The adapters are in
`tools/bench/candidates.go`; every candidate is used only through its public API. The safety probes use each
candidate's default settings, without the resolvers the W3C harness adds.

## How each row is computed

- **W3C rows**: one harness for every candidate, the same list of cases and the same rule as `TestW3CSuite`: a case
  passes when the verdict (valid or invalid) matches the suite's expectation. No verdict (a library limit, an
  unsupported construct, a timeout of 30 s) counts as a failure, and so does an instance test whose valid schema
  the candidate rejected. Cases libxml2's one-file compilation cannot run (several schema documents, hints only)
  count as failed for libxml2.
- **Without contested cases**: the same results without the 133 cases chosen by the criteria in
  [contested-cases.md](contested-cases.md); the criteria depend only on the suite and the standards, not on results.
- **Agreement with libxml2**: for every in-scope instance test that both run, the same verdict, and for invalid
  documents the same line of the first error; every verdict difference is listed and categorised in
  [differences-libxml2.md](differences-libxml2.md) (generated by `tools/compare -docs w3c`).
- **MF rows**: every schema compiles with imports resolved from the local catalogue; every document gets its
  expected verdict.
- **Added to a program**: size of a "compile a schema, validate a file" program (`tools/bench/sizeprog`) minus the
  same program without a validator, `CGO_ENABLED=0 go build -ldflags="-s -w"`; for libxml2 the size of its shared
  library.
- **Time and memory**: each candidate in a fresh process (`bench perf-one`) compiles the JPK_V7M(3) schema and
  validates the generated file; wall time measured in that process (for `xmllint`, around the process) and maximum
  resident set size of the process (`getrusage`). Each candidate and size runs `-runs` times (5 by default), the
  runs of different candidates interleaved; the tables show the median and `perf.json` keeps every run. Validators
  that build a tree of the whole document are not run on 200 MB.
- **1 GB document**: peak Go heap during streaming validation (`TestStreamingMemory`).

## Raw results

[`docs/results/`](results/) holds the output of the last published run:

- `w3c-verdicts.tsv`: every in-scope W3C case, its expected verdict and each candidate's verdict (`valid`,
  `invalid`, `undecided`, or `-` when the candidate could not run it);
- `w3c.json`, `contested.json`, `corpus.json`, `perf.json`, `size.json`, `probes.txt`: the per-mode summaries;
- `environment-<mode>.json`: date, goxsdgo commit, Go version, operating system, CPU, number of cores, load
  average, `xmllint` version and the version of every module the run used.

## Running it again

```sh
go -C tools/fetch run . -root ../..                        # inputs (W3C suite, MF schemas and samples), checksummed
go -C tools/bench run . -root ../.. w3c                    # W3C suite, every Go candidate (and goxsdgo with 5e names)
(cd tools/compare && go run -tags libxml2 . w3c)           # W3C suite through libxml2 (needs libxml2 and pkg-config)
go -C tools/bench run . -root ../.. -docs contested        # contested cases, docs/contested-cases.md
go -C tools/bench run . -root ../.. corpus                 # MF corpus
go -C tools/bench run . -root ../.. -xmllint $XMLLINT probe   # safety, features, errors, patterns
go -C tools/bench run . -root ../.. size                   # program size
go -C tools/bench build -o ../../out/bench/bench . && \
  (cd tools/bench && ../../out/bench/bench -root ../.. -xmllint $XMLLINT -runs 5 perf 20 60 200)   # time and memory
go -C tools/bench run . -root ../.. publish                # copy the raw results to docs/results
GOXSDGO_STREAM_MB=1024 go test ./xsd -run TestStreamingMemory -v   # 1 GB document
```

libxml2 is pinned to release 2.15.4: the official source archive is
`https://download.gnome.org/sources/libxml2/2.15/libxml2-2.15.4.tar.xz`, SHA-256
`98087fd181d9070724f3fbc65c7377db03038eb92bd882374daff44940138821` (the published run used the Homebrew build of the
same release). A package of another version can give different libxml2 numbers. To build it:

```sh
curl -LO https://download.gnome.org/sources/libxml2/2.15/libxml2-2.15.4.tar.xz
shasum -a 256 libxml2-2.15.4.tar.xz   # 98087fd1…40138821
tar xf libxml2-2.15.4.tar.xz && cd libxml2-2.15.4
./configure --prefix="$HOME/libxml2-2.15.4" --without-python && make && make install
export PKG_CONFIG_PATH="$HOME/libxml2-2.15.4/lib/pkgconfig" XMLLINT="$HOME/libxml2-2.15.4/bin/xmllint"
```

On macOS with Homebrew (while it still ships 2.15.4), `tools/compare` needs `PKG_CONFIG_PATH=/opt/homebrew/opt/libxml2/lib/pkgconfig`; `xmllint`
is taken from `PATH` or given with `-xmllint`. Give it explicitly: macOS ships an older `/usr/bin/xmllint`
(libxml2 2.9.13), which is noticeably faster on these files and is not the version compared here; with Homebrew
`XMLLINT=/opt/homebrew/opt/libxml2/bin/xmllint`. `environment-perf.json` records the version that was used. `tools/bench` builds with Go 1.27 because jacoelho/xsd requires it.
Results land in `out/` (not committed) until `publish` copies them.

## Known limits of the numbers

- The W3C rows count verdicts only, not error codes or positions.
- Time and memory come from one machine, named in `environment-perf.json`, a laptop also used for other work. In
  the published run the spread of the 5 runs was under 5% in every row; between sessions on a differently loaded
  machine absolute times can move more than that, the order of the candidates did not.
- knroy/go-xml is also an XSD 1.1, XPath, XQuery and XSLT processor, which explains most of its size.
- A schema rejected by a candidate for a limit or an unsupported construct counts as a failure, as it does for
  goxsdgo.
